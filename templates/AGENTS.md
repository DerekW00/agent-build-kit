# Project build workflow

Follow the task's actual constraints and existing project rules. Use AI, internet access and imported materials only where allowed. Do not change security settings, install global tools, or add background automation implicitly.

- State the user-visible result, acceptance criteria, important assumptions and smallest working slice.
- Explain consequential choices against credible alternatives. Separate human decisions, delegated agent choices and unaccepted suggestions. Unknown reasons stay unknown.
- Implement incrementally. Prefer existing project tools and small, testable boundaries. Avoid unrelated refactors and unnecessary frameworks.
- Read generated code. Verify required behavior and relevant failures with independent expectations. Inspect actual output before claiming a check passed.
- Keep one writer per journal or checkpoint. Link canonical records rather than duplicating them. Keep secrets and private data out of notes.
- Before a demo, reconcile notes with the implementation. Label fake/live integrations, incomplete work and unverified claims.
- For a long-session interruption, save the current objective, evidence, blockers and one next action. Do not commit, publish or message others merely to create a checkpoint.

Installed skills are optional aids. This file does not override the user's instructions or grant new tool authority.
