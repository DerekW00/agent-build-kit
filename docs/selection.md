# Why this kit is small

A private laptop inventory found many aliases, cached versions, provider copies and task-specific integrations. It was a static inventory, not proof that every skill was enabled or safe. Raw inventory, personal settings and private integrations are not part of this public repository.

The selection criterion is useful engineering behavior with little setup: produce a working slice, make decisions explainable, verify actual results, and preserve enough context to continue. These are original, concise workflows; third-party plugin bundles are not vendored.

| Included method | Benefit | Cost and boundary |
| --- | --- | --- |
| Build session | Turns a request into observable acceptance criteria and a working slice | Keep the contract short; do not demand a large design document |
| Build journal | Records consequential options, reasons and evidence for review | One writer; no exhaustive-option claim or invented rationale |
| Verify change | Challenges generated code against independent expectations | Select checks by actual risk; avoid ritual test expansion |
| Session handoff | Supports interruptions and provider switches | One short snapshot linked to canonical records; no repeated status loop |
| Technical research (design add-on) | Resolves a blocking question with version-matched evidence | No open-ended survey or mandatory connector |
| System design (design add-on) | Makes data, interfaces and failures concrete | No invented scale targets or mandatory large document |
| Design review (design add-on) | Challenges the mechanism with counterexamples | One bounded pass; recommendations do not accept risks for the user |

## Optional, depending on the task

- UI design skills when a UI is actually being judged.
- Database migration or security review skills when those changes exist.
- MCP Inspector for a real MCP server, not every agent application.
- Git worktrees for useful parallel work with clear ownership.
- Selected verification guidance from a reviewed upstream source.

## Excluded from the default

- Personal context, career records, private company knowledge and account integrations.
- Raw global provider settings, permission bypasses, credentials and hook commands.
- Whole workflow bundles that impose approval stages, extensive plans or repeated review regardless of task size.
- Autonomous loops, background orchestration, transcript observers and automatic communication/publication.
- Unreviewed remote skill downloads or scripts executed merely because an installer recommends them.

No skill can make the model's explanation historically true. Review the source of an important decision. If the source supplies no reason, keep that reason unknown; label new analysis as analysis. A test suite validates the covered software behavior, not the truth of the journal or interview readiness.
